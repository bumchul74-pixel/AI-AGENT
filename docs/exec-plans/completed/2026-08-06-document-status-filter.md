# 문서 상태 검색 조건 추가

## 목표

문서관리 목록에서 색인 상태를 검색 조건으로 선택하고, 프로젝트와 상태가 함께 적용된 결과와 총 건수를 조회한다.

## 제약

- 프런트엔드는 검색 조건만 전달하며 DB 필터 규칙을 중복 구현하지 않는다.
- 목록과 총 건수는 동일한 프로젝트·상태 조건을 사용한다.
- 기존 무한 스크롤과 전역 Toast 정책을 유지한다.

## 비목표

- 색인 상태 종류나 상태 전이 규칙은 변경하지 않는다.
- 삭제된 문서를 검색 결과에 포함하지 않는다.

## 현재 상태

문서 목록은 프로젝트 조건만 화면에서 선택할 수 있어 사용자가 상태별 결과를 조회할 수 없다.

## 단계

1. 문서 목록 API에 선택적 `indexStatus` 조건을 연결한다.
2. 서비스와 MyBatis 목록·건수 조회에 같은 조건을 적용한다.
3. 문서관리 목록 영역에 상태 선택 UI를 추가하고 조회 훅에 연결한다.
4. 상태 필터 테스트, 프런트 빌드, 기본 검증 게이트를 실행한다.

## 검증

- `DocumentServiceTest`의 상태별 목록 및 총 건수 검증: 통과
- `frontendCheck`: 통과
- `verifyAll`: 통과 (`test`, `integrationTest`, `ragTest`, `frontendCheck`, 문서 검증 포함)

## 위험 및 롤백

잘못된 조건 연결 시 목록과 총 건수가 불일치할 수 있다. 문제가 발생하면 선택적 상태 파라미터와 필터 SQL/UI 연결을 함께 되돌려 기존 프로젝트 조회로 복구한다.

## 결정

페이지 이동 중 결과가 섞이지 않도록 상태가 바뀌면 첫 페이지부터 다시 조회한다. 상태 값은 서버의 `IndexStatus` 열거형을 사용한다.
