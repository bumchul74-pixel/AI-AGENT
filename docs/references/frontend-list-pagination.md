# 프런트엔드 목록 페이징 표준

## 기본 방식

이 프로젝트의 대용량 목록은 서버 페이지 API와 프런트엔드 append 방식을 함께 사용한다.

1. 최초 조회는 `page=0`, `size=30`으로 요청한다.
2. 사용자가 현재 목록 끝에서 80px 이내에 도달하면 다음 페이지를 서버에서 조회한다.
3. 새 응답은 기존 목록을 교체하지 않고 안정적인 식별자를 기준으로 중복을 제거하여 append한다.
4. 동시에 두 번 요청하지 않도록 in-flight 잠금을 사용한다.
5. 서버의 `last` 또는 `hasNext` 값을 기준으로 추가 조회를 종료한다.
6. 검색어, 필터 또는 정렬 조건이 바뀌면 누적 목록과 페이지 상태를 초기화하고 0페이지부터 다시 조회한다.

서버는 전체 데이터를 한 번에 반환하지 않는다. 안정적인 정렬과 `page`, `size`, 전체 건수, 다음 페이지 존재 여부를 반환해야 한다. 프런트엔드는 이미 받은 데이터는 유지하며 다음 페이지 조회 실패를 공통 오류 Toast로 알린다.

## UI 규칙

- 최초 조회와 추가 조회 상태를 구분한다.
- 추가 조회 중에는 기존 목록을 유지하고 목록 하단에 로딩 상태를 표시한다.
- 모든 데이터를 받은 경우 종료 상태를 표시한다.
- 자동 스크롤 감지를 사용할 때 키보드와 접근성 보완을 위해 명시적인 `다음 데이터 불러오기` 동작도 제공한다.
- 명시적인 페이지 번호 이동은 업무상 임의 페이지 이동이 필수인 화면에서만 제품 명세에 예외를 기록한 뒤 사용한다.

## 구현 기준값

- 기본 페이지 크기: 30건
- 추가 조회 임계값: 스크롤 하단 80px
- 병합 키: 해당 데이터의 안정적인 ID
- 오류 처리: 기존 목록 유지 + 전역 Toast
## 공통 목록 및 테이블 컴포넌트

- 독립 스크롤과 footer가 필요한 목록 화면은 `frontend/src/components/common/ScrollableListLayout.jsx`를 사용한다.
- 모든 표 형식 목록은 raw `<table>`을 화면에서 직접 구성하지 않고 `frontend/src/components/common/DataTable.jsx`를 사용한다.
- `DataTable`이 `<table>`, `<thead>`, header cell, `<tbody>`와 행 반복 구조를 소유한다. 화면은 column 정의와 cell renderer만 제공한다.
- 공통 테이블은 `border-collapse: separate`를 사용하고 header의 `thead`와 `th`를 스크롤 영역 상단에 고정한다.
- 고정 header cell은 반드시 완전히 불투명한 `surface-subtle` 배경을 사용하고 본문보다 높은 z-index를 가져야 한다. 투명색, 반투명색 또는 정의되지 않은 CSS 변수는 금지한다.
- header 아래에는 경계선 또는 그림자를 적용하여 스크롤되는 행과 시각적으로 분리한다. 행의 텍스트와 배경은 어떤 스크롤 위치에서도 header를 통해 보이거나 header content와 겹치면 안 된다.
- 페이지별 CSS는 목록 높이, column 너비와 cell 표현만 확장하고 공통 스크롤·table·고정 header 구조를 다시 구현하지 않는다.
- 새 표 목록은 스크롤 중 header 겹침 여부와 light/dark theme의 불투명 배경을 확인한다.
