# 좌측 메뉴 정보구조 표준

## Depth 규칙

- Dashboard는 전역 진입점이므로 독립된 직접 이동 메뉴로 유지한다.
- 1Depth는 사용자의 업무 목적과 책임 영역을 나타낸다.
- 2Depth는 실제로 이동하는 개별 화면을 나타낸다.
- 메뉴 Depth는 자식 개수로 추론하지 않고 navigation 정의의 `type: 'group' | 'page'`로 명시한다.
- `group`은 자식이 한 개여도 항상 펼침 가능한 1Depth로 유지한다.
- 화면 추가나 삭제로 메뉴 Depth가 자동 변경되면 안 된다.

## 현재 표준 구조

| 1Depth | 2Depth |
| --- | --- |
| Dashboard | 직접 이동 |
| AI 작업 | AI 대화, 소스 생성, PPT 생성, 생성 이력 |
| 지식 관리 | 프로젝트 관리, 문서 관리 |
| 데이터 탐색 | RAG 조회, Neo4j 데이터 탐색 |
| 분석 및 품질 | Java Graph, 소스 품질, Secure Coding |
| 운영 관리 | 시스템 상태, Agent 설정 관리, 통합 데이터 삭제 |

## 분류 기준

- 데이터 저장소의 조회·검색·탐색 화면은 `데이터 탐색`에 배치한다.
- 프로젝트와 색인 대상 문서의 생명주기는 `지식 관리`에 배치한다.
- 소스의 관계·품질·보안 판정은 `분석 및 품질`에 배치한다.
- 시스템 상태, 실행 정책 설정과 파괴적 정리 작업은 `운영 관리`에 배치한다.
- API와 데이터 모델이 다른 화면은 하나의 화면으로 억지로 합치지 않고 동일 1Depth 아래의 별도 2Depth로 구성한다.
